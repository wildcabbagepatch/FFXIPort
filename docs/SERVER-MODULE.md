# fpxport — FFXIPort server module (FPX/1)

File: `server/modules/custom/late/fpxport.lua`
Command: `!fpx` (permission 0). Module name: `fpxport`. Global: `xi.fpxport`.
License: GPL-3.0-only, (C) 2026 wildthing (plus LandSandBoat data, see below).

## What it does

Implements the server side of `docs/PROTOCOL-FPX1.md`:

| Category | Unlock check (LSB API) | Destination |
|----------|------------------------|-------------|
| Home Points (`H`, ids 0–121, not 67) | `hasTeleport(HOMEPOINT, id%32, floor(id/32))` | module table copied from LSB `homepoint.lua` |
| Survival Guides (`S`, menu ids) | `hasTeleport(SURVIVAL, groupIndex-1, group-1)` | LSB `survival_guide_map.lua` (required at runtime) |
| Gate Crystals (`G`, 0–5) | `hasKeyItem(<X>_GATE_CRYSTAL)` | `xi.teleport.destination[xi.teleport.id.<X>]` |
| Runic Portals (`R`, 1–6) | bit `2^id` of `getTeleport(RUNIC_PORTAL)` | `xi.teleport.destination[xi.teleport.id.<X>_SP]` |

## Travel prices (final, confirmed by the project owner)

| Category | Gil | Alternative currency |
|----------|----:|---------------------:|
| Home Points | 1,000 gil | 100 Conquest Points |
| Survival Guides | 1,000 gil | 100 Conquest Points |
| Gate Crystal Teleports | 1,000 gil | 100 Conquest Points |
| Runic Portals | 1,000 gil | 100 Imperial Standing |

* One fixed price per category for every eligible destination
  (`M.config.prices`). There are no distance/fee multipliers, no key-item
  discounts (Rhapsody in White) and no key-item exemptions (Captain Wildcat
  Badge); RC1/RC2 had these and they were removed in RC3.
* The only exception is **same-city travel, which is free** (next section).
* The server is authoritative: the snapshot carries every destination's
  offer, and the client shows exactly that. A `GO` carries the price the
  player saw, and any difference is refused with `PRICE` without charging.
  Funds are checked before any debit. A free trip requires no funds and
  calls no currency API.

## Same-city free travel

A trip costs 0 gil, 0 CP and 0 IS when the character's **current zone** and
the **destination zone** belong to the same city (`M.sameCity`). Unlock,
state and zone checks still apply.

City membership (`M.cityGroupOfZone`) is generated by
`tools/gen_city_groups.lua` from three LandSandBoat sources:

1. **Cities are the non-zero LSB Home Point groups** (`homepoint.lua` `group`,
   the groups LSB itself uses for its free-within-group Home Point fee).
2. A zone **with** a Home Point belongs to that Home Point's group, or to no
   city when LSB gives it group 0. This includes Kazham, Mhaura, Selbina,
   Nashmau and Al Zahbi, whose LSB entry has group 0.
3. A zone **without** a Home Point belongs to city G only if LSB marks it as
   `type: [city]` (`data/zones/<zone>/zone.yaml`), **and** its conquest region
   (`src/map/utils/zoneutils.cpp`, `GetCurrentRegion`) is the region of all
   of G's Home Point zones, **and** no other city has Home Points in that
   region.

Result (24 zones):

| City (LSB group) | Zones |
|------------------|-------|
| 1 San d'Oria | Southern / Northern / Port San d'Oria, **Chateau d'Oraguille** (no Home Point; Sandoria region, city) |
| 2 Bastok | Bastok Mines, Bastok Markets, Port Bastok, Metalworks |
| 3 Windurst | Windurst Waters / Walls, Port Windurst, Windurst Woods, **Heavens Tower** (no Home Point; Windurst region, city) |
| 4 Jeuno | Ru'Lude Gardens, Upper / Lower / Port Jeuno |
| 5 Adoulin | Western / Eastern Adoulin |
| 6 Tavnazian Safehold | Tavnazian Safehold |
| 7 Aht Urhgan | Aht Urhgan Whitegate, **The Colosseum** (no Home Point; WestAhtUrhgan region, city) |
| 8 Norg | Norg |
| 9 Rabao | Rabao |

The rule applies to every category. In practice only Home Points and
Survival Guides have destinations inside cities; Gate Crystal and Runic Portal
destinations are never city zones, so they are always paid.

## Travel checks (in order; nothing is charged unless all pass)

1. Request grammar, version, RID (`BADREQ`, `VERSION`).
2. Replay cache: same client session id **and** RID within 30 s → the final cached outcome is re-sent, nothing re-executed. A reloaded client (new session id) reusing a RID is treated as a new request (RC4). Missing or malformed session id → `BADREQ`.
3. GO cooldown 5 s after an accepted trip (`BUSY`); SYNC ≤ 6 per 10 s (`BUSY`).
4. Destination exists and has a full position (`BADDEST`).
5. Unlocked (`LOCKED`).
6. Zone: not in an instance, battlefield or Mordion Gaol (`ZONE`).
7. State: not dead, in an event, engaged, with enmity, on a chocobo/mount, or zoning in (`STATE`).
8. Not already at the destination (`HERE`, ≤ 10 yalms in the same zone).
9. Payment method offered (`PAYMENT`); expected price equals current price (`PRICE`); free trips must be requested as free.
10. Sufficient balance (`FUNDS`), only for paid trips.
11. Transaction (next section).

## Transaction and final outcome (RC2 hardening, RC3 corrections)

Travel is split into a side-effect-free **validation** (`M.planGo`) and a
**transaction** (`M.executeGo`). Each request id ends in exactly one final
outcome. That outcome is stored in the replay cache before it is sent:

| Final outcome | Reply | When |
|---------------|-------|------|
| moved | `T` | debit succeeded (or free), `setPos` succeeded, or it raised but the move demonstrably took effect / zoning to the destination started |
| not charged | `E INTERNAL` | validation raised; the debit raised without taking anything; or a free trip could not start |
| refund confirmed | `E INTERNAL` | a refund was made **and** the re-read balance equals the pre-charge balance |
| uncertain | `E UNSURE` | the debit or the move raised and the outcome could not be read, or a refund raised / could not be verified |

Step by step:

| Step | Handling |
|------|----------|
| Validation | Any exception → `E INTERNAL`; nothing was charged. |
| Debit | Returned normally → charged. Raised → the balance is re-read. Unchanged → not charged. Reduced → that amount is refunded and confirmed (→ `INTERNAL`, or `UNSURE` if not confirmed). Unreadable → `UNSURE`, with no guessed refund. |
| Accepted reply | Post-charge balances are read if possible, otherwise derived from the validated pre-charge balances. `T` is cached, then sent. Send failures are logged and do not abort a paid trip; the command handler never raises. |
| Move | If `setPos` raises, the server never assumes success or failure; it checks (`M.moveStarted`: at the destination, or `getZone(true)` reports zoning there). Moved → `T` stands. Unknown → `UNSURE`, no refund. Verifiably not moved → refund **and confirm** → `INTERNAL`; otherwise `UNSURE`. |
| Correction | When the move fails after `T` was sent, the final `E` is sent **immediately for the same request id** and replaces `T` in the cache (PROTOCOL-FPX1.md §4.6). The client then turns the accepted trip into failed (`INTERNAL`) or uncertain (`UNSURE`). |

Player notices (plain text, besides the protocol frames):

* "…your payment was refunded." Only when the refund is confirmed by the balance.
* "…nothing was charged." Debit without effect, or a free trip.
* "…the payment status could not be confirmed. The server operator has been notified; please check your balance." For every `UNSURE`.

**Currency incidents.** Every `UNSURE` outcome logs one line through `M.log`
(`print`, i.e. the map-server log):

```
[fpxport] CURRENCY INCIDENT char=<id> rid=<rid> sid=<session id> stage=<debit|move|refund>: <what> | travel <cat> <dest> -> zone <zone> | <cur> <price> (amount <n>) balance before=<n> observed=<n|nil> | error=<message> | manual check required
```

The same record (char, rid, sid, stage, what, cat, dest, zone, cur, price, amount,
before, observed, err, t) is kept in `xi.fpxport.incidents` (last 100).
`UNSURE` keeps the 5 s travel cooldown. A confirmed refund releases it.
Duplicate or retried requests (same session id and request id) replay the final
outcome and can never cause a second debit, refund or move. The cooldown and
rate limits are per character and apply across client sessions.

## Installation (XI: Forever Offline / Phoenix)

1. Copy `fpxport.lua` to `server/modules/custom/late/` (or any module folder).
2. List it in `modules/init.txt`, e.g. `custom/late/fpxport.lua`, unless the
   folder is already listed.
3. **Disable the previous FFXIPort server module** (`custom/late/ffxiport.lua`).
   If `init.txt` lists the file itself, remove or comment out that line. If it
   lists a folder that contains the file (e.g. `custom/late/` or `custom/`),
   every module file in that folder is loaded, so a file-specific line is not
   enough: move `ffxiport.lua` out of the `modules/` tree or delete it. Moving
   it out works in both cases. Both modules can be loaded at once (different
   file, module name and command), but the new client only speaks FPX/1, so
   the old module serves no purpose. Removing `fpxport.lua` follows the same
   rule.
4. Restart the map server. No SQL and no core file changes are needed.

## Loader compatibility

* With `xi.module.registerCommand` (current LSB): the command is registered
  through it.
* Without it: the command table is assigned to `xi.commands.fpx`, which is
  where LSB's `CCommandHandler` looks commands up, and re-asserted in an
  override of `xi.server.onServerStart`.
* The file returns its `Module` object, which older loaders expect and newer
  loaders ignore.
* **Not verified on the actual XI: Forever Offline / Phoenix build.** The
  module was written against upstream LandSandBoat `base`. All 193 client
  catalogue rows (104 Home Points, 77 Survival Guides, 6 Gate Crystals, 6 Runic
  Portals) match it in id, zone, city group and unlock bit
  (`tools/verify_catalog_vs_lsb.lua`). Before acceptance, run that tool and
  `tools/gen_city_groups.lua` against the real Phoenix tree.
